# Stream Hub 1.3.0 canary and rollback runbook

This runbook is an approval gate, not authorization to deploy. Run it only in
an approved maintenance window. Keep operator credentials, the host address,
and the channel-to-ID map outside the repository.

## 1. Fixed scope

| Item | Value |
| --- | --- |
| Candidate unit | `stream-1-3-canary.service` |
| Candidate HTTP port | `8879` |
| Candidate install root | `/opt/stream-1.3-canary` |
| Candidate data root | `/var/lib/stream-1.3-canary` |
| Candidate config | `/var/lib/stream-1.3-canary/stream.json` |
| Candidate artifact | `stream-transcode-1.3.0-linux-x86_64-lgpl.tar.gz` |
| Candidate artifact SHA-256 | `9c950c8daf11f0cef675a2d31d6722a3ec89a3070a310d1a78ee4b5b372e9345` |
| Candidate Git commit | `d0d204697ae123ad569acf58e6d2ca7f3f5e447d` |
| Candidate Stream binary SHA-256 | `bc81a560f9f16228b4cfd29f5354295e26ec4950b5628079c029429263b00332` |
| Baseline production version | `1.2.6` |
| Baseline production binary SHA-256 | `beb0b3279581ca26c75990c87cbfcd565fa459702b699d7a8b7867aa8839c195` |

Port `8879` was not listening at the time this runbook was prepared. Confirm it
again immediately before deployment. Do not reuse an existing canary port.

The private operator channel map must provide four IDs:

```bash
CANARY_CHANNEL_PRIMARY=...
CANARY_CHANNEL_COPY=...
CANARY_CHANNEL_COPY2=...
CANARY_CHANNEL_POL=...
```

The canary includes only these four streams and the CAM definitions they
reference. It explicitly excludes:

- edits to the production configuration or production database;
- migrations outside `/var/lib/stream-1.3-canary`;
- changes to firewall, routing, sysctl, or network interfaces;
- stopping or restarting `stream.service`;
- changing CC/PES alarm thresholds;
- copying channel-specific gateway, watchdog, or HLS workarounds into the
  product.

## 2. Preflight and evidence directory

Set operator-local values without writing credentials to shell history. Use a
mode-`0600` netrc file for API authentication.

```bash
set -euo pipefail

CANARY_UNIT=stream-1-3-canary.service
CANARY_PORT=8879
CANARY_ROOT=/opt/stream-1.3-canary
CANARY_DATA=/var/lib/stream-1.3-canary
CANARY_CONFIG=/var/lib/stream-1.3-canary/stream.json
ARTIFACT=/root/stage/stream-transcode-1.3.0-linux-x86_64-lgpl.tar.gz
ARTIFACT_SHA256=9c950c8daf11f0cef675a2d31d6722a3ec89a3070a310d1a78ee4b5b372e9345
BACKUP=/root/back/streamhub-1.3.0-canary-$(date -u +%Y%m%dT%H%M%SZ)
EVIDENCE="$BACKUP/evidence"

test "$(uname -m)" = x86_64
test -f "$ARTIFACT"
printf '%s  %s\n' "$ARTIFACT_SHA256" "$ARTIFACT" | sha256sum -c -
if ss -ltn | awk '{print $4}' | grep -Eq '(^|:)8879$'; then
  echo 'ABORT: canary port is already listening' >&2
  exit 1
fi
if systemctl is-active --quiet "$CANARY_UNIT"; then
  echo 'ABORT: canary unit is already active; inspect it before proceeding' >&2
  exit 1
fi
install -d -m 0700 "$BACKUP" "$EVIDENCE"
```

Record the private channel map as a mode-`0600` file under `$BACKUP`; do not
commit it. Resolve all four IDs before continuing.

## 3. Backup before any write

Capture the production baseline and any previous canary installation. Missing
optional paths are recorded rather than treated as empty backups.

```bash
systemctl show stream.service >"$BACKUP/stream.service.show"
systemctl cat stream.service >"$BACKUP/stream.service.unit"
systemctl status stream.service --no-pager >"$BACKUP/stream.service.status" || true
journalctl -u stream.service -n 300 --no-pager >"$BACKUP/stream.service.journal"
sha256sum /opt/stream/stream >"$BACKUP/production-binary.sha256"
cp -a /etc/systemd/system/stream.service "$BACKUP/"
cp -a /var/lib/stream/stream.json "$BACKUP/production-stream.json"

if test -e "$CANARY_ROOT"; then cp -a "$CANARY_ROOT" "$BACKUP/previous-root"; fi
if test -e "$CANARY_DATA"; then cp -a "$CANARY_DATA" "$BACKUP/previous-data"; fi
if test -e "/etc/systemd/system/$CANARY_UNIT"; then
  cp -a "/etc/systemd/system/$CANARY_UNIT" "$BACKUP/previous-unit"
fi

find "$BACKUP" -maxdepth 3 -type f -exec sha256sum {} + \
  >"$BACKUP/backup-files.sha256"
```

Before installing, copy only the four selected stream records and their CAM
dependencies into a fresh canary configuration. Do not point the canary at the
production data directory. Review the generated JSON for exactly four stream
IDs and validate it with `jq -e .`.

## 4. Candidate installation

Extract to a staging directory, verify provenance, then rename the staging
directory into the fixed canary root. The production install remains untouched.

```bash
STAGE=$(mktemp -d /opt/stream-1.3-canary.stage.XXXXXX)
tar -xzf "$ARTIFACT" -C "$STAGE" --strip-components=1
grep -Fx 'Stream-Version: 1.3.0' "$STAGE/STREAM_BUILD_INFO.txt"
grep -Fx 'Git-Commit: d0d204697ae123ad569acf58e6d2ca7f3f5e447d' \
  "$STAGE/STREAM_BUILD_INFO.txt"
grep -Fx 'Binary-SHA256: bc81a560f9f16228b4cfd29f5354295e26ec4950b5628079c029429263b00332' \
  "$STAGE/STREAM_BUILD_INFO.txt"
sha256sum "$STAGE/bin/stream-bin"
file "$STAGE/bin/stream-bin" | grep -F 'x86-64'

# Only after the backup and config review:
if test -e "$CANARY_ROOT"; then
  mv "$CANARY_ROOT" "$BACKUP/replaced-root"
fi
mv "$STAGE" "$CANARY_ROOT"
```

The dedicated unit must use only:

```text
WorkingDirectory=/opt/stream-1.3-canary
ExecStart=/opt/stream-1.3-canary/run.sh -c /var/lib/stream-1.3-canary/stream.json -p 8879 --data-dir /var/lib/stream-1.3-canary --web-dir /opt/stream-1.3-canary/web
```

After reviewing the complete unit file, run `systemd-analyze verify` on it,
then `systemctl daemon-reload` and start only `stream-1-3-canary.service`.

## 5. Ten-minute acceptance gate

Create one status JSON per channel every five seconds for at least ten minutes.
The API credential belongs only in the private netrc file.

```bash
CANARY_URL=http://127.0.0.1:8879
NETRC=/root/.stream-canary.netrc
CHANNELS=(
  "$CANARY_CHANNEL_PRIMARY"
  "$CANARY_CHANNEL_COPY"
  "$CANARY_CHANNEL_COPY2"
  "$CANARY_CHANNEL_POL"
)

systemctl is-active --quiet "$CANARY_UNIT"
curl --netrc-file "$NETRC" -fsS "$CANARY_URL/api/v1/metrics" \
  >"$EVIDENCE/version.json"

for sample in $(seq 1 120); do
  stamp=$(date -u +%Y%m%dT%H%M%SZ)
  for channel in "${CHANNELS[@]}"; do
    curl --netrc-file "$NETRC" -fsS \
      "$CANARY_URL/api/v1/stream-status/$channel" \
      >"$EVIDENCE/status-${channel}-${stamp}.json"
  done
  sleep 5
done

journalctl -u "$CANARY_UNIT" --since '-12 minutes' --no-pager \
  >"$EVIDENCE/canary.journal"
```

For every channel, both the first and last samples and the complete delta set
must prove:

- `on_air=true` for the full observation window;
- non-zero bitrate with no sustained drop and no unexplained step change;
- CC delta exactly `0` and PES delta exactly `0`;
- `cw_applied_primary + cw_applied_backup` increases across observed odd/even
  transitions;
- no partial CW is accepted without the matching cached half and generation;
- zero CW values are never applied;
- reconnects or candidate rejections do not form a repeating degradation
  pattern.

Do not weaken CC/PES thresholds to pass this gate.

Run an external decoder independently for every selected output:

```bash
for channel in "${CHANNELS[@]}"; do
  timeout 660 ffmpeg -hide_banner -nostdin -v warning -t 600 \
    -i "$CANARY_URL/play/$channel?internal=1" \
    -map 0:v:0 -map 0:a:0 -f null - \
    2>"$EVIDENCE/ffmpeg-${channel}.log"
done
```

Each FFmpeg run must decode video and audio for ten minutes and exit
successfully. Reject the candidate if any output has recurring PPS, MMCO,
macroblock, invalid-data, AC-3, timestamp, continuity, or PES errors. HTTP 200,
byte flow, UI `ONLINE`, and a running process are not sufficient evidence.

For buffer failover, record the primary-loss timestamp, backup activation
timestamp, primary-healthy timestamp, return timestamp, and configured hold and
recovery gate values. Failover must stay within the configured bounds and must
not introduce CC/PES or decoder errors.

## 6. Acceptance and abort criteria

Accept only when all four channels pass all gates and the evidence directory
contains version, status series, journal, and four FFmpeg logs. Abort on any
failed invariant, unexpected database migration, port collision, service
restart outside the canary unit, or missing evidence.

No production promotion is part of this runbook. Promotion requires a new
approval that names the production unit, maintenance window, backup path, and
the accepted evidence directory.

## 7. Canary-only rollback

Rollback stops only the canary unit. Preserve the failed candidate under the
same timestamped backup instead of deleting it.

```bash
systemctl stop "$CANARY_UNIT"
if test -e "$CANARY_ROOT"; then
  mv "$CANARY_ROOT" "$BACKUP/failed-root"
fi
if test -e "$CANARY_DATA"; then
  mv "$CANARY_DATA" "$BACKUP/failed-data"
fi

if test -d "$BACKUP/previous-root"; then
  cp -a "$BACKUP/previous-root" "$CANARY_ROOT"
fi
if test -d "$BACKUP/previous-data"; then
  cp -a "$BACKUP/previous-data" "$CANARY_DATA"
fi
if test -f "$BACKUP/previous-unit"; then
  cp -a "$BACKUP/previous-unit" "/etc/systemd/system/$CANARY_UNIT"
  systemctl daemon-reload
  systemctl start "$CANARY_UNIT"
else
  systemctl disable "$CANARY_UNIT" || true
fi
```

If a previous canary was restored, repeat the status and FFmpeg probes against
that version. Finally verify that the production service version, binary hash,
process start time, and external playback remained unchanged throughout the
canary operation.
