# Если не работает

## Диагностика за 2–3 минуты

Пройдите шаги по порядку. После каждого шага у вас должен быть понятный результат.

1. **Проверьте, что сервер жив и UI отвечает**
   - Команда:
     ```bash
     ss -lntp | grep ':9060' || true
     curl -I "http://127.0.0.1:9060/"
     ```
   - Ожидаемо: порт слушается, HTTP отвечает `200/302`.
2. **Проверьте состояние входа в UI**
   - В `Dashboard` у stream: `Input = ONLINE`, `bitrate > 0`.
   - Если `OFFLINE` или `0`, выход не появится.
3. **Проверьте input URL и протокол**
   - Частая причина: неверный URL, порт, логин/пароль, неподдерживаемый формат.
   - Для multicast проверьте сетевой маршрут и IGMP.
4. **Проверьте выход и сеть**
   - Для HTTP-TS: путь `http://SERVER:9060/live/STREAM_ID` (без `.ts`).
   - Для HLS: путь `http://SERVER:9060/hls/STREAM_ID/index.m3u8`.
   - Убедитесь, что порт открыт между клиентом и сервером.
5. **Проверьте авторизацию**
   - Если включена auth, проверьте пользователя, пароль и client headers.
   - При тестах не выключайте auth в публичной сети.
6. **Проверьте системные логи Stream**
   - Команда:
     ```bash
     journalctl -u stream@prod.service -n 200 --no-pager
     ```
   - Ищите ошибки по id канала и по input/output.
7. **Проверьте нагрузку и ресурсные лимиты**
   - CPU, RAM, диск, сеть.
   - При FULL-транскоде убедитесь, что `ffmpeg` доступен и не в ошибке.
8. **Если проблема не ушла**
   - Снимите 50–100 строк логов вокруг ошибки и параметры stream.
   - Сравните с [FAQ](../faq.md) и [Логами](logs.md).

## Частые ситуации

### Web UI не открывается

- Проверьте порт и firewall.
- Убедитесь, что процесс запущен с нужным `-p`.
- Для systemd проверьте статус сервиса:

```bash
systemctl status stream@prod.service --no-pager
```

### Канал OFFLINE / bitrate = 0

- Проблема обычно во входе: URL, доступность хоста, multicast/network policy.
- Проверьте вход отдельно `ffprobe`/`ffplay` с того же сервера.

### Выход включён, но не играет

- Проверяйте в порядке: `Input` → `bitrate` → `output URL` → сеть/ACL.
- Если это HLS, проверьте, что плейлист и сегменты реально отдаются.

## Ожидаемая “здоровая” картина в UI

- Stream в состоянии `ONLINE`.
- Битрейт стабильный и не равен нулю.
- Ошибки в Log не накапливаются сериями.
- Клиенты (если есть) подключаются и получают данные.

## Онлайн логи

```bash
journalctl -u stream@prod.service -f
```
