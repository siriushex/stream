# audit_report

## Контекст и метод

- Объект: `https://stream.centv.ru` (MkDocs + Material).
- Подход: discovery по структуре `docs/` + `mkdocs.yml`, сверка live-страниц, техпроверки ссылок/сборки.
- Ограничение: без радикальной смены IA и без изменения продуктовых функций.

## IA и навигация

- Основной путь пользователя сохранён: `Главная → Быстрый старт → Руководство/FAQ`.
- В `mkdocs.yml` навигация структурирована логично: onboarding отдельно, manual отдельно.
- Секция `Руководство → Settings` перегружена количеством подпунктов, но без критичной путаницы.

## 10 пользовательских сценариев (до правок)

| Сценарий | Статус до | Наблюдение |
|---|---|---|
| 1. Новый пользователь знакомится с продуктом | P1 | На главной не хватало короткого onboarding-пути “что делать прямо сейчас”. |
| 2. Быстрый старт: поднять 1 поток | P1 | Шаги были разбросаны, не хватало статусов и явного “первого результата”. |

| 4. Нужен systemd | P2 | Информация есть, но не в одном ясном “потоке действий”. |
| 5. Нужен выбор LITE/FULL | P2 | Есть, но не везде единообразно подчеркнута связь с Transcode. |
| 6. Нужна безопасная установка | P1 | HTTPS/HTTP fallback описан, но без сильного “HTTPS-first + local review” акцента. |
| 7. Нужна проверка/диагностика | P1 | Не хватало “2–3 минуты диагностики” с последовательными шагами. |
| 8. Нужен апдейт | P2 | Информация присутствует, но разбросана между FAQ и manual. |

## Контент и тон

- Найдена несогласованность тона: часть страниц сухие и технические, часть — более промо.
- Найдена разная детализация терминов между страницами Quick Start и FAQ.
- Найдены дубли смыслов (установка/обновление/диагностика) без единого сценарного “моста”.

## Док-техническое качество

- `mkdocs build --strict`: PASS.
- Внутренние ссылки/якоря в собранном `site/`: `missing_count 0`.
- Live-страницы (главная/установка/faq/troubleshooting): HTTP 200.
- Критичных проблем разметки не найдено.

## Безопасность коммуникации

- Риск: у пользователей старых CentOS часто включается HTTP fallback для installer.
- До правок предупреждение было, но недостаточно акцентировало “аварийный путь” и проверку источника.
- Отсутствуют публичные checksum-артефакты на сайте; это не баг docs, но операционный риск доверия.
